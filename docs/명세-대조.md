# 1차 MVP 기능명세서 대조 결과

작성 2026-08-15 · 프론트
기준 문서: [제대로 — 1차 MVP 기능명세서](https://app.notion.com/p/3bd2355cf2bd8099a84ac057b5b11f3c) (2026-08-09)

---

## 결론

**OpenAPI 계약은 명세서를 거의 정확히 반영하고 있습니다. 어긋난 쪽은 확정 시안입니다.**

이전에 정리한 `백엔드 요청 15건`은 대부분 **명세에서 벗어난 시안을 구현하려고
명세 밖 필드를 요청하는 것**이었습니다. 그대로 보냈으면 안 됐습니다.

백엔드에 실제로 요청할 것은 **3건**이고, 나머지는 **기획·디자인이 정할 사안**입니다.

> **2026-08-15 결정**: 선택지 목록 셋(부위·직전 상황·피부 변화)은 **시안대로 갑니다.**
> 이 셋은 계약 enum 과 명세를 함께 고쳐야 하므로 아래 `1-3` 으로 옮겼습니다.

## 1. 백엔드에 요청할 것 (3건)

### 1-1. VAPID 공개키 전달 경로

F-01(17:30 피부 점호 알림)이 P0이고, 명세 11.2에서 알림 구현 방식은
프론트·백엔드가 정하게 되어 있습니다. Web Push 구독은 `applicationServerKey`
없이는 만들 수 없습니다.

요청: 환경변수로 받을 수 있게 키 전달 (또는 `GET /push-config`).

### 1-2. 오늘의 관리 항목 형식 (낮은 우선순위)

F-04의 `doToday` / `avoidToday` / `checkNext` 는 계약에서 `string[]` 입니다.
시안은 항목마다 굵은 제목 + 설명 두 줄이라, 지금은 첫 문장을 잘라 제목으로 쓰고 있습니다.
한 문장만 오면 설명 줄이 빕니다.

요청: `{ title, description }[]` 로 나눠 주세요. 명세 11.2의 기술 협의 사항입니다.

### 1-3. 선택지 enum 3종 변경 (결정 완료 — 시안 채택)

기획이 시안 쪽으로 결정했습니다. **계약 enum 과 명세 문구를 함께 고쳐야 합니다.**

#### 부위 `BodyArea`

```
현재  WHOLE_FACE, LEFT_FOREHEAD, CENTER_FOREHEAD, RIGHT_FOREHEAD, NOSE,
      LEFT_CHEEK, RIGHT_CHEEK, AROUND_MOUTH, LEFT_CHIN, RIGHT_CHIN,
      LEFT_JAWLINE, RIGHT_JAWLINE, NECK, OTHER

변경  FOREHEAD      이마          (좌·중·우 → 하나로 합침)
      LEFT_CHEEK    왼 볼
      RIGHT_CHEEK   오른 볼
      NOSE          코
      AROUND_MOUTH  인중
      CHIN          턱            (좌·우 → 하나로 합침, 턱선 없앰)
      EYE_AREA      눈가          ← 신규
      TEMPLE        관자놀이       ← 신규
      OTHER         기타
```

`NECK`(목)이 얼굴 맵에서 빠집니다. 목 불편은 `기타` + `otherAreasNote` 로 갑니다.

#### 직전 상황 `Situation`

```
추가  OUTDOOR_ACTIVITY   야외 활동
      DIET_CHANGE        식습관 변화
      STRESS             스트레스
      SKIN_CONTACT       피부접촉 환경

분리  SWEAT_OR_DUST_AFTER_TRAINING
      → TRAINING   훈련/운동
      → SWEAT      땀/과피지
```

기존 `SHAVING` · `PROTECTIVE_GEAR_OR_MASK` · `DELAYED_WASHING` · `NEW_PRODUCT` ·
`TOUCHED_OR_SQUEEZED` · `SLEEP_DEPRIVATION` · `NONE_RECALLED` 는 그대로입니다.
`OTHER` 는 신규 4종이 생기면 필요 없어집니다.

> ⚠️ **관리 규칙표 v0.1 도 함께 갱신해야 합니다.**
> F-04 는 `직전 상황 규칙` 을 조회해 오늘의 관리를 만듭니다.
> 신규 4종에 대응하는 규칙이 없으면 그 상황을 골라도 규칙이 걸리지 않아
> 공통 규칙만 남습니다. 훈련/운동과 땀/과피지를 나눈 것도 규칙 매핑이 필요합니다.

#### 피부 변화 `SkinChange`

```
현재  IMPROVED, SIMILAR, WORSENED, NEW_AREA, UNSURE
변경  IMPROVED, SIMILAR, WORSENED          (뒤 둘 삭제)
```

`NEW_AREA`(새로운 부위에도 생겼어요)가 없어집니다.
번짐 신호는 보고 시점의 관리 전 확인 `짧은 시간에 빠르게 넓어지고 있어요` 가 받습니다.
다만 **경과 시점에는 번짐을 표현할 방법이 없어집니다.** 감수하는 것으로 봅니다.

#### 프론트 처리

`src/api/designOptions.ts` 가 지금 시안 어휘 → 계약 enum 대응표를 들고 있습니다.
enum 이 바뀌면 그 표는 필요 없어지므로 파일을 지웁니다.
그때까지는 `턱·눈가·관자놀이 → OTHER`, 신규 상황 4종 → `OTHER` 로 보냅니다.

## 2. 시안이 명세를 벗어난 지점 (기획·디자인 결정 필요)

아래는 **백엔드 요청이 아니라 시안을 명세에 맞출지 결정할 사안**입니다.
계약을 바꾸면 명세를 어기게 됩니다.

### 2-0. 겉모습에서 `진물` 이 빠졌습니다 ⚠️

명세 F-02 참고 일러스트는 8종인데 시안은 6종이고 **진물·딱지가 없습니다.**
F-03 에 전용 절과 수용 기준이 있습니다.

> - [ ] 진물과 딱지는 서로 다른 값으로 저장된다
> - [ ] 진물 선택 시 관리 전 확인에 미리 반영된다

진물을 고를 수 없으면 `관리 전 확인` 의 `고름·진물·물집` 을 미리 켜 주지 못합니다.
사용자가 그 화면에서 직접 고르므로 **의료진 확인 분기 자체는 동작하지만**,
P0 수용 기준 두 줄을 못 지킵니다.

**제안: 타일 두 장(진물·딱지)을 추가합니다.** 계약은 이미 맞습니다.

### 2-1. 결과 5번째 카드 — P0 기능이 빠지고 제외 범위가 들어왔습니다 ⚠️

| | |
| --- | --- |
| 명세 | **F-06 이전 유사 경험** (P0). 유사도 5점 이상 1건 표시 |
| 시안 | **04 INGREDIENT GUIDE / 추천 성분 보기** (`25:30820`) |

- 5.3 제외 범위에 **`제품 성분 분석`** 과 **`제품 추천과 구매 연결`** 이 명시돼 있습니다.
- 14. 핵심 통합 수용 기준에 **`완료 기록 한 건부터 이전 경험으로 표시한다`** 가 있습니다.
- 2.5 제품 목표의 네 번째 항목이 이전 경험 참고입니다.

즉 **P0 필수 기능을 빼고 그 자리에 제외 범위를 넣은 것**입니다.
계약의 `careResult.similarExperience` 가 원래 이 카드입니다.

**제안: 카드를 `이전 유사 경험` 으로 되돌립니다.** 계약 변경 없이 바로 됩니다.

### 2-2. `현재 피부 상태` 질문 — 제외 범위입니다 ⚠️

시안 피부보고2(`25:30577`)의 마지막 질문(건조함/유분많음/속건조/민감함)은
5.3 제외 범위의 **`피부 타입 진단`** 에 해당합니다.
F-00 정책에도 `피부 타입을 온보딩에서 받지 않습니다` 가 있습니다.

더 큰 문제는 이 질문이 명세 F-03의 필수 항목인 **`느껴지는 불편`**
(가려움/따가움·화끈거림/누르면 아픔/가만히 있어도 아픔/열감/당김/특별한 느낌 없음)을
화면에서 밀어냈다는 점입니다.

**제안: 이 질문을 뺍니다.** `느껴지는 불편` 은 AI 가 한 문장에서 뽑고
`보고 내용 확인`(F-03)에서 사용자가 수정하므로 별도 질문 화면은 필요 없습니다.

> 프론트에서 이미 관련 버그를 고쳤습니다 — 피부 타입 답을 `sensations` 로 옮겨 보내면서
> AI 가 뽑아 둔 `따가움` 을 덮어쓰고 있었습니다. 지금은 덮어쓰지 않습니다.

### 2-3. 선택지 목록 — 결정 완료

부위·직전 상황·피부 변화 셋은 **시안대로 가기로 했습니다.** `1-3` 참고.
겉모습(진물·딱지)은 명세대로 되돌리는 쪽으로 `2-0` 에 남겨 뒀습니다.

### 2-4. 의료진 확인 경과에 물으면 안 되는 질문이 있습니다

시안 `25:28735` 은 의료진 확인 분기에서도 `안내받은 관리를 어떻게 실행했나요?` 를 묻습니다.
F-05 정책은 정반대입니다.

> 일반 관리 안내를 받지 않은 사용자에게 행동 실행 여부를 묻지 않습니다.

계약의 `ClinicianFollowUpRequest` 에 `actionCompletion` 이 없는 건 **의도된 설계**입니다.

**제안: 의료진 분기에서 그 질문을 뺍니다.**

### 2-5. 기록조회·이력상세의 트러블 묶음

시안은 `이어서 확인할 기록` · `시작일` · `4일째` 처럼 **여러 날을 잇는 묶음**을 그립니다.
명세 7.1은 `피부 보고는 하루 한 건만 저장합니다` 이고, F-06 기록 목록·상세도 한 건 단위입니다.

**제안: MVP 범위 밖으로 봅니다.** 남은 일정에 데이터 모델을 바꾸는 건 무리입니다.

### 2-6. 기본 알림 시각 변경

F-07 정책이 `P0에서는 알림 시각을 17:30으로 고정합니다` 이고,
5.2 P1 목록에 `알림 시간 변경` 이 있습니다.
계약의 `NotificationSettings.time: const '17:30'` 은 명세대로입니다.

**시안의 온보딩 시각 선택 휠(`25:30666`)이 P1 기능을 P0 화면에 넣은 것**입니다.

**제안: 화면은 두되 값은 17:30 고정으로 안내하거나, 화면을 뺍니다.**
(날짜별 점호 예외는 P1보다도 밖이라 요청하지 않습니다.)

### 2-7. STREAK

명세 어디에도 없습니다. 5.3 제외 범위의 `피부 점수와 랭킹` 과 인접한 성격입니다.

**제안: 카드를 빼거나, 남긴다면 계약 변경 없이 지금처럼 근사값으로 둡니다.**

### 2-8. 마케팅 정보 수신 동의

F-00 저장 데이터는 `consentVersion` · `consentedAt` 하나뿐이고,
명세가 말하는 동의는 `개인정보·민감정보 수집·이용` 필수 동의입니다.
마케팅 동의는 명세에 없습니다.

**제안: 항목을 빼면 계약 변경이 필요 없습니다.**
남긴다면 선택 동의는 법적으로 별도 저장이 필요하므로 그때 백엔드에 요청합니다.

### 2-9. 시안 재업로드(2026-08-15)로 생긴 추가 차이 🆕

이 문서를 백엔드에 보낸 뒤 와이어프레임이 통째로 다시 올라왔습니다.
노드 ID가 `22:*` → `25:*` 로 전부 바뀌었고, 선택지에 두 가지가 달라졌습니다.

**(1) `지금 관리할 수 있는 상태` 가 넷에서 둘로 줄었습니다**

| | 값 |
| --- | --- |
| 계약 `CareAvailability` | `BEFORE_WASH_CAN_WASH_LATER` · `ALREADY_WASHED` · `CAN_CARE_BEFORE_SLEEP` · `ADDITIONAL_CARE_DIFFICULT` |
| 시안 (`25:30577`) | `세안 전` · `세안 완료` |

뒤 둘을 고를 방법이 없습니다. **지금 관리할 수 없는 사람이 그 사실을 알릴 자리가 없어집니다.**
관리 규칙표가 `취침 전` · `관리 불가` 로 갈라지는 규칙을 갖고 있다면 그 규칙은 걸리지 않습니다.

**확인 필요: 타일 둘을 되살릴지, 계약에서 두 값을 뺄지.**

**(2) `세안 지연` 타일이 `여드름을 짬` 으로 바뀌었습니다**

| | 값 |
| --- | --- |
| 계약 | `DELAYED_WASHING` · `TOUCHED_OR_SQUEEZED` |
| 시안 (`25:30577`) | `여드름을 짬` · `피부 만짐` — 둘 다 `TOUCHED_OR_SQUEEZED` 로 접힘 |

`DELAYED_WASHING` 은 사용자가 고를 수 없게 됩니다.
다만 결과·이력 화면의 예시에는 `상황: 세안 지연` 이 그대로 나오므로,
그 값은 **AI 가 한 문장에서 뽑아 주는 것**으로 보고 계약에 남겨 뒀습니다.

> 1-3 의 `직전 상황 Situation` 요청에 이 한 줄이 추가됩니다 —
> **`분리 TOUCHED_OR_SQUEEZED → SQUEEZED(여드름을 짬) / TOUCHED(피부 만짐)`**.
> 나누지 않으면 서버는 둘을 구분하지 못합니다.

**(3) `보고 내용 확인` 두 번째 줄이 다릅니다**

시안(`25:28859`)의 여섯 줄은 `부위 / 피부 상태 / 겉모습 / 불편 / 직전 상황 / 현재 상태` 입니다.
프론트는 두 번째 줄이 `다른 부위 추가 설명`(`otherAreasNote`)입니다.

시안의 `피부 상태`(예: `붉은 여드름`)에 대응하는 계약 필드가 없습니다.
반대로 `otherAreasNote` 는 **버릴 수 없습니다** — 턱·눈가·관자놀이를 고르면
`OTHER` 로 가기 때문에 그 라벨을 여기 실어 보내야 정보가 남습니다(1-3 참고).

**확인 필요: `피부 상태` 줄이 무엇을 보여주는 자리인지.**
부위 enum 이 확장되면(1-3) `otherAreasNote` 줄이 필요 없어지므로 그때 정리됩니다.

**(4) 화면 자체의 변화** (계약과 무관, 프론트에서 이미 반영)

- 온보딩 마스코트에서 `?` 가 빠지고 그림이 279×194 로 커졌습니다
- 온보딩2 에 `알림을 받지 않을게요` 갈래가 생겼습니다
- 상황 타일 아이콘이 12종 모두 서로 다른 그림으로 채워졌습니다
- `한 문장 피부보고` 화면에서 진행 표시가 빠졌습니다(2~4 단계만 표시)
- `보고 내용 확인` 의 `다시 작성할래요` 버튼이 빠졌습니다 — 뒤로가기로 대신합니다

## 3. 시안에 없는데 명세가 요구하는 것

### 3-1. 피부 기록 전체 삭제 (F-07, P0)

F-07 메뉴에 `피부 기록 전체 삭제` 가 있고 수용 기준도 있습니다.

> - [ ] 전체 기록 삭제 전에 확인창이 표시된다

시안 설정(`25:28903`)에는 이 항목이 없습니다. 계약에도 기록 전체 삭제 엔드포인트가 없습니다
(`DELETE /me` 는 계정 삭제입니다).

**확인 필요: 계정 삭제로 갈음할지, 별도 기록 삭제를 넣을지.**
별도로 간다면 이게 백엔드 요청 3번째 항목이 됩니다.

### 3-2. 안내가 달라진 이유 (F-04)

F-04 결과 출력 구조에 `적용된 직전 상황과 현재 관리 상태를 태그로 표시합니다` 가 있습니다.
시안의 결과 카드에는 이 태그가 없고, 프론트도 구현하지 않았습니다.

**확인 필요: 넣을지 뺄지.**
